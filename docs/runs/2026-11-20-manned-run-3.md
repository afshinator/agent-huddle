## New observations (filed, not fixed — this run was for observation)

1. **`launch_guard: warn` writes nothing a human sees** (#48). `src/coordinator.ts:291-294` logs the
   record and stops there: no stderr line, unlike the refusal path (`src/index.ts:48`) and unlike #46's
   `warn`. A supervisor watching the room never learns they are in a repo root.
2. **An empty agent message is committed** (#49). `messages.jsonl` has
   `{"kind":"agent","from":"lead","text":"","mentions":[],"hop":2}`: a lead turn that produced no text
   was appended unconditionally (`src/turn-loop.ts:219`), printed as `[@lead] ` and pushed to the other
   agents as empty context.
3. **A child's stderr lands in the room surface** (#50). `[pi:dev1] Warning: No project session found
   with id 'dev1'; creating a new session with that id.` appeared in the coordinator's pane, mixed with
   the chat: `src/real/pi-agent-client-real.ts:246` writes child stderr to `process.stderr`.
4. **A deliberate stop is recorded as a crash** (#51). dev1's pane text ends
   `[exited]` then `[error] pi process for dev1 exited unexpectedly`, although Ctrl-C in the room pane is
   the documented shutdown. `shutdown()` sets `shuttingDown` before `stdin.end()`
   (`src/real/pi-agent-client-real.ts:192-205`), so the child most likely took the terminal's SIGINT
   itself — the guard at `:252` then fires because the client's orderly stop raced the signal. lead's
   pane text ends with `[exited]` only, so the ordering is racy.

## Run note corrections

- Pane labels are `label`, not `terminal_title`. `herdr pane list` reports the coordinator's rename as
  `label: "@lead"`; `terminal_title` stays `null` for a shell pane and carries the *process* title
  (e.g. `π - yasf`). The command has been fixed below.
- The boot line for the `warn` guard does not appear in the room pane (#48). Only `refuse` prints.
- `herdr pane run <pane> ./launch-run3.sh` works: one word, no quoting to lose. Do not pass an inline
  `sh -c '…'` (the #37 finding).

## Commands that worked

```bash
herdr pane list | jq -r '.result.panes[] | "\(.pane_id) \(.label // "-")"'   # labels, not titles
herdr pane read <pane> --source recent-unwrapped | tail -40
herdr pane run <pane> "@dev1 write notes/footer.txt …"                       # a room message
herdr pane run <dev1 pane> "also check the footer"                           # a pane line
herdr pane send-keys <room pane> C-c                                         # clean shutdown
jq -c '{status, chain: .chain.status}' rooms/run3/state.json                  # active → idle
jq -c 'select(.kind=="user") | {text, mentions}' rooms/run3/messages.jsonl
```

## Cleanup verified

- after Ctrl-C: `state.json` `{"status":"idle","chain":null}`; both agent panes closed by the
  coordinator; no `pi --mode rpc` child left; no `tail -f` left; the room pane returned to its shell.
- the worktree holds only agent output (`notes/`, `rooms/run3.yaml`, `launch-run3.sh`, and the ignored
  `rooms/run3/`); nothing was committed, and the worktree was removed afterwards.
- no JSON record reached a pane; `agents/<id>/log.jsonl` stayed the machine record.

## Limits of this evidence

- Two agents, one provider (`commandcode`: `deepseek-v4-pro` lead, `deepseek-v4.1-flash` dev1), one hop
  pattern, and a task small enough to finish in two turns. `@all`, three or more agents, and a `DONE`
  fight are still unproven.
- The panes were closed at shutdown — correctly — so their content is quoted here from the session and
  from `output.log`, not from a pane that can be re-read afterwards.
- One probe renamed dev1's pane label to `dev1-probe` while checking whether `pane rename` reaches
  `terminal_title`. The room was idle and nothing else was affected.
