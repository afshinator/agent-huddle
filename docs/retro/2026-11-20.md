# Retrospective — 2026-11-20

## Scope

Review of the v1 implementation session for `agent-huddle`, from initial spec work through T1–T10 and the post-implementation issue fixes. The implementation is complete and the review-created GitHub issues are closed.

## Findings

### High — no repository CI guardrail

`package.json` exposes `bun test` and `bun run typecheck`, but the repository has no `.github/workflows/` workflow and no pre-commit hook. The session repeatedly had to run these checks manually. A CI job would have caught regressions before pushes and made the completion claim reproducible for another agent or contributor.

Action: GitHub issue #10 adds a pull-request/push workflow for the existing commands.

### Medium — tests were not always run at the most useful boundary

The session often ran the full suite after implementation, but several failures were discovered only after broad changes (for example, the initial T6 queue behavior and the T8 controlled-RPC fixture). The repository has no documented focused-check convention beyond the ticket text. Future tickets should name the first focused test command before the full suite.

Action: retain focused test commands in ticket DoDs; no separate issue because this is process guidance rather than missing product behavior.

### Medium — environment instructions were not followed mechanically

The session used `find`, `cat`, `sed`, and ad-hoc Python JSON parsing despite `/Users/afshin/.pi/agent/AGENTS.md` preferring `fd`, `read`, and `jq`. The violations did not affect the product, but they created avoidable tool churn and made the run less reproducible.

Action: future runs should treat the tool substitutions as mechanical guardrails. No repository issue: the rule already exists in the global AGENTS file.

### Low — controlled integration fixtures were introduced late

The real `pi` and `herdr` integrations initially depended on live environments. The deterministic controlled-RPC coordinator fixture was added only after review identified the missing real multi-agent composition proof. Starting T8 with a local RPC fixture would have reduced model calls and shortened the debugging loop.

Action: for future process-boundary tickets, create a deterministic protocol fixture before the live smoke test. No open product issue remains.

### Low — reviewer delegation lacked the diff in one subagent namespace

The code-review subagent could not inspect the git diff because its read-only namespace lacked shell/git access and the diff was not passed into its prompt. The parent review recovered by reading the diff directly, but this wasted a review slot.

Action: pass a saved patch path or file list/content explicitly to read-only reviewers, and verify their available tools before dispatch. No repository issue.

## What worked

- Tracer-bullet tickets gave each implementation step a bounded DoD.
- Fake seams enabled fast deterministic tests before real `pi`/`herdr` integration.
- Proof-driven issue filing found real defects after the initial implementation: state recovery, aborted turns, RPC final text, concurrency, telemetry, routing, integration coverage, and prompt-file validation.
- The final repository state was repeatedly verified with `bun test` and `tsc --noEmit`.

## Suggested environment changes

1. Add CI for `bun test` and `bun run typecheck` (issue #10).
2. Keep focused checks in every ticket's DoD.
3. Pass review artifacts explicitly to subagents instead of assuming git access.
4. Continue using controlled protocol fixtures before live service smoke tests.
5. Follow the global tool substitutions mechanically.
