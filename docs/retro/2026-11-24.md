# Retrospective — 2026-11-24

## Scope

The session that shipped four things: the chat-line format, gate-cost rules for room prompts, a
`ticket-resolver1-claims` template, and claim-check's coverage report (`lint` → `UNACCOUNTED`), then ran
`007-ticket-52`, reviewed its fix, merged it and closed the ticket. 796 tool calls, 578 of them bash, 70
error-bearing — of which the largest single class was file slices the `read`-tool guard refused.

## Findings

### High — a quoted pipe is read as a command separator, so a question turn cannot gather evidence

`~/.pi` extension `_system/extensions/answer-only.ts` blocks mutating bash on a question turn by splitting
the command on `;`, `&&`, `||` and `|`, then requiring every segment to be a known read. The split ignores
quoting, so `rg -n "a|b" src` becomes a segment `b" src` and is refused:

```
rg -n "a|b" src                          -> false (refused)
gh issue list --json number -q ".[] | .number" -> false (refused)
cd /x && git status --porcelain          -> true  (correct)
```

Four calls were refused this way in this session, each an `rg` with alternation or a `jq` filter with a
pipe, and each was the natural way to ask the question being answered. The effect is not wasted calls so
much as a weaker answer: the agent either asks again or answers without the evidence it wanted.

Action: issue filed — split on separators outside quotes, with fixtures for the three shapes above.

### High — claim-check's committed build can lag its source, and the parity check does not cover `lint`

`bin/claim-check` execs `bin/claim.mjs`; `bin/claim.ts` is the source. This session edited the source, ran
the wrapper, saw no change and briefly concluded the new report did not work. It was a stale artifact
built 75 minutes earlier.

AC15 compares the two runtimes' output on two fixtures (`line-exact/pass.json`, one `computed` case), which
covers `run`. It does not cover `lint`, so a `lint`-only change can ship inert with the whole suite green —
exactly what would have happened had the rebuild been forgotten.

Action: issue filed — rebuild to a temporary file and byte-compare against the committed artifact, so
"the artifact is current" is one command and one assertion.

### Medium — finance-hub typechecks a gitignored directory

`tsconfig.json` includes `**/*.ts` and excludes only `node_modules` and `scripts`, so `_run/**` — gitignored
and full of the throwaway probes agents leave behind — is part of `npm run check`. Three stale probes in
`_run/005-ticket-68/` imported an absolute path from a worktree that no longer exists, and `npm run check`
exited 2 on `main` before this session's merge. The debris came from earlier runs of this same workflow, so
it recurs by construction.

Action: issue filed — exclude `_run` and `probes` in `tsconfig.json`.

### Medium — already fixed in this session, recorded because it was the largest cost

Both checkers were dispatched with "verify every factual claim" while the ticket's `claims` block had
already answered 24 structural claims in 0.15 s. One settled in 24 s; the other spent 71 tool calls and 25
minutes, 11 of them database queries, re-deriving what the block held. Prompts now carry a command budget, a
"do not re-derive what is settled" rule and a single-query database rule (D30); coverage is reported by
`lint` (D31, AC20), and `test/template-prompts.test.ts` refuses a template that lacks either.

### Low — no pointer from the always-loaded file to the claims tool

`rooms/templates/*/prompts/*.md` now invoke
`~/Documents/dev/_system/tools/claim-check/bin/claim-check`, and `agent-huddle/AGENTS.md` neither names the
tool nor its skill. Time went into locating it, and for a while into the superseded research prototype
whose `field-set` still takes `lines` instead of `symbol`. A pointer costs one line.

Action: add one line to `AGENTS.md` under Rooms.

### Low — the claims block is extracted from the body by hand, repeatedly

`gh issue view N --json body | awk '/^```claims/{f=1;next} …' | jq` appeared eight times. Every one was
correct, so this is not a defect; a `claim-check show --from-issue N` would make it one command. Not worth
building until it is wrong.

### Low — global `AGENTS.md` carries rules that change nothing

Two lines are sediment: the list of tools not to write rules about (`bat`, `eza`, `sd`, … none installed)
is a rule about a rule, and it protects against a mistake already deleted; the BSD-userland paragraph
overlaps the tool-substitution paragraph directly above it. Both can go without changing behaviour. The
rest of that file earned its load this session — the read-tool rule, the temp-dir rule and the
package-manager-follows-the-lockfile rule each prevented a class of error that would otherwise have been
silent.

## What worked

- The `read`-tool guard on shell slices. It refused roughly ten calls and every refusal was correct: the
  transcript's `sed -n` habit is a token sink.
- Recording a decision (D30, D31) at the moment it was made, with the measurement. Both were written from
  numbers taken in the session, so the "why" survives without re-deriving it.
- Pinning prompt text with a test while the prompts were still being edited: `test/template-prompts.test.ts`
  was red until both templates carried the rules, and it will stay red if a later edit drops one.
