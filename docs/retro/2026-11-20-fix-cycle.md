# Retro — the issue-fix cycle (2026-11-19 → 11-20)

Session: `01a1f544`. 112 user turns, 851 tool calls, 70 error-bearing results (8.2%).
Span: 2026-11-19T19:24 → 2026-11-20T04:25, one compaction. Scope: closed #10–#27, then the
RCA's six process changes.

Bash mix (516): `bun test` 88, `gh issue` 65, `rg -n` 62, `bun run` 44, `sed -n` 32,
`cat >` 30, `git add` 30, `nl -ba` 23, `perl -0pi` 16. Counts are behaviour: the loop this
session actually ran was read → edit → test → commit → close, once per issue.

Prior retro (`2026-11-20.md`) covered the environment. This one covers what the *repo* should
carry so the next agent does not rediscover it.

---

## 1. The two-command gate is manual, and there is no navigation file

**Evidence:** 88 `bun test` + 44 `bun run` calls, nearly always chained by hand as
`bun test 2>&1 | tail -N && bun run typecheck 2>&1 | tail -2`. There is no `check` script and no
`AGENTS.md`/`CLAUDE.md`; the norms an agent needs (the ticket loop, `PI_TEST_INTEGRATION`,
the RCA's failure-table requirement) live in `README.md`, `docs/SPEC.md` and
`docs/rca/2026-11-20-v1-defects.md`, and were re-read rather than pointed to.

**Fix:** `"check": "bun run typecheck && bun test"` in `package.json`, and an `AGENTS.md` that is
nothing but pointers: gate command, where the failure grammar lives, the ticket loop, the live-test
command, the probe convention. CI already runs the same two commands (`.github/workflows/ci.yml`),
so the script makes local and CI identical instead of adjacent.

## 2. Probe and runtime artefacts land in the tracked tree

**Evidence:** `.gitignore` is `node_modules/`, `.DS_Store`, `*.log`. During the session,
`.probe-audit.ts`, `.probe-r6.ts`, `.probe14b.ts`, `.router.bak`, `rooms/.probe-24.yaml`,
`rooms/probe23/` were all written inside the repo, and `rooms/probe23/` (messages, telemetry, agent
logs) was created by a probe that booted a real room. One probe yaml with `handle: "@here"` started
two real `pi` agents and opened two herdr panes that outlived the process and had to be closed by
hand.

**Fix:** ignore `*.bak`, `probes/`, and `rooms/*/` (directories, so the shipped `rooms/*.yaml` stay
tracked); state the convention: probes live in `probes/` with a non-dot name, and a probe that boots
a room sets `HERDR_ENV=0`. `test/hygiene.test.ts` already fails on dot-prefixed TypeScript files.

## 3. Bulk `sed`/`perl` edits broke working states four times

**Evidence:** `error TS2304: Cannot find name 'what'` after a perl rewrite; the `readMessages`
signature change needed three repair rounds across 27 test call sites; one `perl -0pi` on
`test/coordinator.test.ts` left a nonsense line (`pi.spawn(lead, { cwd: dir })` with no second
spawn) that had to be reverted by hand. `cat >` heredocs also produced 14 empty-command errors and
were used to create files the `write` tool creates directly.

**Fix:** no new machinery. A rule in `AGENTS.md`: new file → `write`; existing file → `edit`;
a mechanical multi-site change → `edit` per site and `bun run typecheck` after each file, not
`sed`/`perl` chains whose failure mode is a silent mangled store.

## 4. The live adapter path went 20+ commits untested

**Evidence:** 4 tests skip by default, CI sets `PI_TEST_INTEGRATION=0`, and nothing prompted a live
run. `#18` rewrote the real client's record handling and `#19` deleted a branch in it with no live
coverage behind either until a manual `bun test test/pi-real.integration.test.ts` in the `#19` turn
— that run passed in 2.5s and cost almost nothing. The manned two-agent room still has never run.

**Fix:** `"test:live": "PI_TEST_INTEGRATION=1 bun test"` plus the AGENTS pointer, so the expensive
path is one command rather than a remembered incantation.

## 5. Push-then-poll burned wall time

**Evidence:** 12+ `sleep 45 && gh run list --limit 1` pairs, ~10 minutes of deliberate sleep, and
one `gh run list --json headline` that exited 1 (wrong field name). `gh run watch --exit-status`
blocks once, prints the result, and exits non-zero on failure.

**Fix:** AGENTS pointer: push, then one `gh run watch --exit-status`.

## 6. Repeated `rg`-with-escaped-parens mistakes (minor)

**Evidence:** two failures, `unopened group` / `unclosed group`, from writing `rg "\(fail\)"` as if
it were basic regex; ripgrep is PCRE-ish by default and needs `rg "\(fail\)"` → `rg '\(fail\)'` with
`-P`, or simply `rg "fail"`. Low cost, but it recurs across sessions.

**Fix:** none beyond the pointer; noted so the next agent recognises it.

## What this retro did not cover

- Whether the fixes actually shorten the next cycle. The gates added (hygiene test, `failOn` knobs)
  are new; their hit rate is unmeasured.
- The RCA's own open item: no manned room run. Ranked above is "make it one command", not "run it".
- Turn-level attribution: the 70 error-bearing results were not classified by cause (tool syntax vs
  a genuine red test vs an environment fault), so 8.2% is an upper bound on avoidable failures.
